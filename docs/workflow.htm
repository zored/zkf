ZKF workflow

How I build and flash my keyboards today, and where it is heading.

Now

QMK 2020 fork, Docker build

Firmware v2.2.1 on every QMK board. One build path, a different flasher per board.

Change a keymap

  1. Edit config.yaml.
  2. ./project.sh build <kb>: Node compiler + qmkfm/qmk_firmware in Docker, fork zkf_stable_planck.
  3. Firmware lands in firmwares/.
  4. Enter the bootloader, flash from the host.
  5. Commit config.yaml + example/; tag v* for a final release.

Later

Upstream QMK, one flasher

Same keymaps on current QMK. Each phase ends with the keyboard check, board by board.

Phases

  1. Baseline: current firmware for all boards in firmwares/, reflashed through QMK Toolbox.
  2. Upstream: build against pinned upstream QMK; fork archived to archive/* tags.
  3. Migrate: template on the current QMK API, YMD09 → Planck → ErgoDox, release v3.0.0.
  4. Docs: per-board pages kept current.
  5. DAO44: current ZMK.
  6. Anne Pro 2: upstream annepro2, Shine, annepro2_tools.
